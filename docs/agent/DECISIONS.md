## P2.1 transaction core (2026-10-29)

- 2026-10-29 · Core in its own library `agent_core` (engraving only) behind `IUndoBackend`: the app uses the master notation's `INotationUndoStack` (UI undo buttons and dirty state follow), unit tests use the score's `UndoStack` directly. Same semantics: prepareChanges = startCmd, commit/rollback = endCmd, one lock bool.
- 2026-10-29 · Transaction order: refuse if locked or a macro is active (E_BUSY, else prepareChanges silently joins someone else's macro) → prepareChanges → clear MScore error → lock → save + clear the user's selection (after prepareChanges, so the macro's own snapshot holds the user's selection for undo). Each step: run, catch exceptions, check the macro is still ours and not unwound, read MScore::_error (non-warning = E_REFUSED, warning = reported and cleared). Any failure rolls back at once. Commit: restore selection inside the macro (redo shows it too) → unlock → commitChanges → notify notationChanged + selectionChanged. Rollback restores the selection after unwind.
- 2026-10-29 · Unwind detection compares the active macro's child count before/after a step: it catches an unwind that removes earlier steps' changes (E_REFUSED, batch rolled back); an unwind in the first step only undoes that step and reports `changed:false`, which is the truth. Each command must check its own effect anyway (rule 3).
- 2026-10-29 · Handles: `<Type>:<eid>@m<bar>[+<offset>].s<staff>.v<voice>[#<fingerprint>]`; resolved by walking the live structure at the location (segments, chords' notes/articulations/lyrics/grace chords, annotations, spanners starting there), matching type + EID + fingerprint (note pitch, chord/rest duration). The EID register is never asked for an object (freed memory, asserts on unknown EIDs); EID text is validated before anything parses it. A new element at a freed address with the dead one's EID would also need the same type, place and fingerprint to be confused with it.
- 2026-10-29 · Write guards (writerunner): E_NO_SCORE; E_MODAL_OPEN via `IInteractive::isCurrentUriDialog`; E_BUSY for text edit, drag, grip/element edit, note input (on the master's interaction and on the part in front); playback is stopped with the `stop` action, not refused (assessment S19). Note input is refused rather than left (leaving it changes the user's state); revisit if it gets in Liam's way.
- 2026-10-29 · Engraving `MessageBox` paths (putNote over a measure repeat, addTuplet with an impossible ratio) cannot be suppressed without an upstream change; commands must validate so those branches are never reached (CORE.md).
- 2026-10-29 · Every write command gets `expectStateVersion` (E_STALE) and returns `stateVersion`, `changed`, `warnings`; stateVersion is current at return because the changes channel delivers synchronously on the main thread. `batch` validates every operation against its schema before anything runs, takes at most 500, and names the failing step; `undo`/`redo` take `steps`, `expectStateVersion`, `expectActionName` and run through the notation in front (so that view repaints), refusing while busy or with E_NOTHING_TO_UNDO.
